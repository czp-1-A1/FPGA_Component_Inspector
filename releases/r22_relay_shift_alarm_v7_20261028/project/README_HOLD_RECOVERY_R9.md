# R9 shared-result recorder with recoverable HOLD

Original classifier, original two display results, ROI thresholds, original page,
Logo, exposure/gain/WB and source-frame/DDR binding remain the R8 baseline.
The recorder consumes actual classified P/E records; UNKNOWN never creates a count.
RECOVERABLE=1 in production only. Default0 retains the legacy module contract.

Association/motion validation precedes modifications. C3 pauses one transaction
and rolls back new identity valid bits. Up to8 missing source opportunities can
retain an armed identity; only an actually returning classified result can count.
Later real crossings queue with their original class/reason/source. Nine absent
opportunities stop publication in CHECK, without filling holes from pitch.
The existing2/4-opportunity grace still depends on actual same-frame anchors.
Finalized E observations cannot drive global speed or steal neighboring P.
Three measured agreements are required before a smaller spacing can change the
association limit. Deferred events preserve missing displacement on numbering.

HOLD can resume on a unique real result. CHECK/LOST need clear/start; this is not
a promise that unobservable pockets can always count. Bad frames/config/source
gaps, multiROI and sustained reverse remain strict. No extra imageRAM/classifier.

SW4up original/down count; SW3up->down starts once. K3+K4 hold1s clears visible
RUN, all totals, last result, all E IDs and first-fault detail. Internal epochs
remain monotonic.300cap. REVIEW is a subset of PRESENT, not an added class.
High16 previously reserved metadata now holds sticky subreason4/track6/gap4/
anchor2; visible RUN low16 and all DDR/CDC widths remain unchanged.

Synthetic28/6 and27/5 arrangements are test patterns, not the user's unknown
remaining E IDs. Real field truth only confirms first E1 and E19 respectively.
Original46 tests retained byte for byte; five new tests include8-gap realRAW
through correction, resize, shared classification, recording and DDR/display.
Software and full fresh route/constraint verification are mandatory before bit
delivery; software simulations do not establish board counting accuracy.
