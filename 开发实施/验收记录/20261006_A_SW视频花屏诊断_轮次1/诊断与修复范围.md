## 已复现缺陷与证据限度

### 1. 新尾行连续回放降低写入 FIFO 余量

使用实际 `roi_sobel_view`、实际 96→128 打包器、`video_in` 和工程自带异步 FIFO；DDR 仲裁使用受控行为模型，未模拟 DDR PHY 或实际控制器。输入每行 256 个 CSI 有效拍，随后 512 个 CSI 空闲拍；CSI 周期 8.888 ns，DDR 周期 15 ns。读占用从写端空闲时开始，共接受 240 个 DDR 命令，中间存在 300 个 DDR 拍（4.5 μs）的有限 ready 暂停。

完整 1024×600 RAW 差异复现如下：

| 条件 | 产生 128 位字 | DDR 写入字 | FIFO 峰值 | 因 full 丢字 | 已写内容差异 |
|---|---:|---:|---:|---:|---:|
| 旧 AWB 直通节奏，同样暂停 | 115200 | 115200 | 506 | 0 | 0 |
| 新公共回放，无 ready 暂停 | 115200 | 115200 | 336 | 0 | 0 |
| 新公共回放，同样暂停 | 115200 | 114960 | 511 | 37 | 0 |
| 仅诊断副本：末两行间插入 512 CSI 拍，同样暂停 | 115200 | 115200 | 507 | 0 | 0 |

新路径最后两行背靠背输出，共 512 CSI 拍／384 个 128 位字。FIFO 已满时内部抑制写入，顶层没有接 full 作完整性保护；末尾剩余 203 字不足固定 240 字传输门槛，继续留在 FIFO。37+203=240，解释本刺激下少一个完整写块。600 行完整字数本来就是 240 的整数倍，不能归因于图像尺寸不整除。

这证明存在“同样条件旧路径通过而新路径丢字”的回归风险，尚未证明现场恰有此 4.5 μs ready 暂停，也未单独解释照片的水平偏移。

仅插入固定尾行 gap 的诊断副本不是可发布修复：它未处理停 CSI、新帧抢占和 `busy` 在 gap 内的语义，不能直接复制到工程。

重跑：仓库根目录执行 `./tmp/sw_edge_flicker_diagnosis_20261005/run_full_frame_probe.ps1`。20 行原始复现在 `tmp/sw_edge_flicker_diagnosis_20261005/ddr_review/`；600 行结果在 `full_frame_20261006/`。

### 2. CSI 停钟时，下一帧可抢占未排出的旧帧尾

`pixel_sof` 会直接清除回放位置和流水状态。最后输入行结束后，当前设计仍需约 512 个 CSI 拍加流水延迟排出末两行；墙上时间的帧间空闲不等于获得足够 CSI 时钟。

最小两帧条件仿真（1024×8）中，连续时钟控制帧完整输出 8192 像素／1536 字；尾行后仅给 40 拍、停钟 1 ms、恢复后 100 拍即开始新帧时，旧帧只输出 6696 像素／1255 字，下一帧完整恢复。

此项仅证明条件性缺陷。DPHY 分频时钟直接经 BUFG 送 ISP；本地 SC500CS 手册及配置表不能确认现场 Clock Lane 是否连续。数据包 LP 图不能作为 Clock 停止的证据。此项也未单独复现照片的水平位移。

证据：`tmp/frame_review_20261005/tb_tail_clock.v`、`tail_console.log`、`tail_wave.wlf`。

### 3. 显示端缺数据后的固定相位问题

`video_out` 按每 16 像素固定相位读 3 个 128 位字并解包；异步 FIFO 在 empty 时拒绝读，但显示相位继续推进，解包逻辑未使用 FIFO empty／valid 保护。这是现有底座的风险，新增视频节奏可能使它更容易暴露。

实际 `video_out` 与实际 FIFO 的两行（2048 像素）专项仿真已完成：无缺数据基线全部正确；人为令第一行前 128 像素期间没有 FIFO 数据返回，24 次 empty 读被 FIFO 拒绝，首次成功取字发生在 x=128，之后全部 1920 个像素精确对应原始连续序列落后 128 像素。第二行左 128 像素就是前行末 128 像素；源 x=700 的橙色标记在两行均显示到 x=828，超出固定 ROI [256,768)，末尾保留 24 个未取词。

这复现了与照片一致的表现机制，尚未确认现场下溢及其触发原因。此专项关闭 DDR 命令，受控注入 FIFO 返回数据空窗；没有将写端尾部丢字和显示端缺数据串联验证。OSD 坐标独立且稳定是 RTL 连接与用户现场反馈，专项不含完整 OSD。

证据：`tmp/display_underflow_20261006/诊断记录.md`、`video_out_underflow.log`、`tb_video_out_underflow.v`、`run.ps1`。

### 4. RGB 行 RAM 映射核对

## 待用户确认的修复范围

建议下一版只修视频传输与位置对齐，保持 1024×600、现有字体／Logo／状态界面、四 KEY 调曝光／增益、SW1 灰度和 SW2 边缘的四种组合。

1. RAW／GRAY 恢复原视频输出节奏，灰度处理只做固定拍数流水，减少不必要的全帧回放。
2. EDGE 回放与 DDR 接收能力协调，保证末行、帧起点、像素位置和打包边界一致；解决尾部连续挤入与新帧抢占，不能仅扩大 FIFO 或添加一个固定 gap 后宣告通过。
3. 为 FIFO 满、显示缺数据、帧字数不完整提供可观察证据与明确恢复，避免缺字后继续以错位图像显示；异常时取样有效状态应反映图像链路完整性。
4. 将真实打包内容、完整 115200 字、DDR 地址、显示坐标纳入四模式回归；加 ready 暂停、帧边界、停 CSI、SW 切换与恢复测试。RTL/TD 通过后生成独立候选镜像，再由用户验证花屏、位置、四 KEY 与四 SW 模式。

正式物料分类、灰度／边缘阈值和算法叠加取舍仍等待稳定画面与实物反馈；本轮不据异常显示评估准确率。

用户之前要求“由我确认再生成”。本轮“继续”用于续接故障诊断；具体修复范围尚待确认，工程 RTL 和旧镜像保持原样。诊断完成不等于修复完成或板卡通过。
