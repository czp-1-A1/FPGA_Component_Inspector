# A检测帧对齐与完整性保护：下一批实施确认稿

2026-10-03。本稿保留最初提出的保护范围；用户后续已批准扩大到帧保护＋ROI灰度统计，且批准中央临时观测框。下文“本批不增加ROI统计”等限制属于最初提案，已被用户新决定更新；实际行为、全帧验证和交付以14说明及ROI灰度统计验收记录为准。当前没有分类判定。

## 要解决的问题

检测候选接口是AWB后、96→128打包前的四像素RGB888。现有显示/DDR使用的`O_tuser`提前53/55拍，不能作为第一组像素的坐标起点；不完整输入仍可能回放缓存旧像素，因此只数AWB输出不能证明采集帧有效。

本轮只读探针验证了AWB内部已存在的`I_tuser_r2`：连续输入、短valid暂停、复位后的完整行，以及残缺行回放时，它均与首组有效像素同拍。探针没有修改RTL。该结论仅覆盖现有1024宽3行场景；尚未验证全600行、前后帧重叠及RAW→demosaic→AWB全链路。

## 最小实现范围

1. **检测专用帧起点。** 保留原`O_tuser`及显示/DDR连接。为检测支路单独引出随像素流水的帧标志，首先验证并使用已有延迟标志；不新增按53拍固定移位的模块。
2. **四像素坐标。** 在检测专用SOF与valid同拍时，从x=0、y=0开始；每个有效拍对应x、x+1、x+2、x+3，无效拍不前进。每行检查256拍，最后一拍含x=1020～1023，600行结束后结束本帧。ready不参与采样和坐标递增。
3. **采集端完整性检查。** 在RAW10解包后、uial2axis之前检查真实FS/FE及每个图像包的像素数，沿用已验证的HS下降后16拍排空规则；必须有600个1024像素图像行且无溢出/通道异常。检查不足排空间隔和FE/末行重合等边界，不能直接沿用累计FORMAT计数。
4. **采集帧与检测帧对应。** 为当前候选帧保留采集起点与处理起点的对应上下文；只有采集端完整、处理端完整且对应关系明确时，发布一次`frame_done`和`frame_valid`。处理先结束或采集先结束都要等待另一侧。新FS抢占、重复处理SOF、上一帧尚未排空或来源不能唯一对应时，候选帧作废，等待新的可对应帧；本批不增加多帧队列。
5. **异常后恢复。** 复位、缺行/短行/超长行、帧中断均不提交有效样本；异常帧后，下一个正常完整帧必须能恢复。停流时不重复发布旧帧。后续结果显示须另行定义等待状态及跨域超时，本批不把“无新帧”显示成空穴。

所有检测逻辑留在现有CSI接收时钟域。本批不增加ROI统计、分类阈值、结果OSD、字体修改、Logo、电机、串口或样本采集功能，不改变视频像素、valid或打包器的连续性。

实现前先复核真实demosaic的帧标志传播与首末行处理；若现有延迟标志不能覆盖该链路，不用三行探针结论替代全链路证据。调参重新配置的作废事件也须先核实跨域来源；没有确认事件接入前，不声称调参期间的样本已得到保护。

## 验证目标

| 场景 | 通过条件 |
|---|---|
| 1024×600完整帧 | 首末四像素坐标准确，完成事件仅一次，输入/处理对应同一帧 |
| 有效拍暂停、ready低 | 坐标保持正确；ready不造成漏采 |
| 少列、少行、超长行、额外像素 | 无有效帧提交，旧RAM数据不补成完整采集帧 |
| FE早到/末行同拍、包排空不足 | 明确作废，不产生误接受 |
| 新FS抢占、处理SOF重复/重叠 | 作废无法唯一对应的帧，不把旧尾部计入新帧 |
| 复位、停流、异常后正常帧 | 无旧帧重复提交；新正常帧恢复 |
| 视频旁路对照 | 像素、valid、原早帧通知及打包数据与基线一致 |

主要使用ModelSim及原厂RAM模型，测试须包含全600行；参考坐标/有效性由独立测试模型生成。接入后完成TD综合、布局布线、资源增量与约束报告；现场由用户验证视频。不能用这一批的接口测试声称分类准确率或完整A验收通过。
