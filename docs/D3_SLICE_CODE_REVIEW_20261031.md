## 1. Slice 用到哪里了

依据 `E:/2026FPGA/.codex_tmp/d3_lossless_physical_r37_20261030/placed_intermediate.area`（布局报告，不是综合估算）：

| 类别 | 实际布局 Slice | 含义 |
| --- | ---: | --- |
| 普通逻辑 | 15413 | 选择、比较、译码、逻辑运算等 |
| 加法/进位链 | 3219 | 算术及工具映射至进位结构的逻辑 |
| 仅寄存器 | 1141 | 没有与上述逻辑合并的寄存器占用 |
| 分布式 RAM | 792 | 用 Slice 实现的存储 |
| 合计 | **20565 / 21216，96.93%** | 余 651 Slice |

寄存器使用率仅 54.09%，ERAM 为 103/108，DSP 为 31/40。减少寄存器位数并不必然同比减少 Slice；也不能把所有小数组都迁入只剩 5 块余量的 ERAM。

若以实际布局低于 95% 为第一阶段目标，需要至少减少 **410 Slice**；低于 93% 需要至少减少 **835 Slice**。这是留余量的工程目标，并不是低于这个百分比就保证布线成功。当前没有成功导出的局部拥塞热点表，不能把任一模块直接认定为全局不收敛的唯一原因。

## 2. 优先级 1：让空穴编号表真正进入专用 RAM

源码：`fpga/component_inspector/user_source/hdl_source/observed_classified_pocket_counter.v:80,257–260,564`；读口上游为 `classified_count_pipeline.v:85,119–125`。

每列 `empty_ids` 是 300×9 bit，当前同步读包含无效地址返回零：

```verilog
always @(posedge clk)
  empty_id <= empty_address < empty_total ? empty_ids[empty_address] : 9'd0;
```

R36 日志 `runs/syn_1/console.log:1457,1460` 的 SYN-5105 明确指出这两个读口无法推断 bram，回退到 dram。**不是 RAM 数组被复位；原始读 always 本身没有复位。** 工具将零填充、复位的地址/计数控制组合识别成不支持的读口形式，单加 RAM 属性没有解决。

进一步按实际综合网表 `d3_camera_gate.v` 的源位置与 `PH1P_PHY_DRAMHARDCON` 实例追溯，两个计数器的 368 个 DRAM LUT 分布如下：

| 对象/源位置 | 每列 RAM 硬宏数 | 两列硬宏数 | 两列 DRAM Slice |
| --- | ---: | ---: | ---: |
| 跟踪表，107 行读口 | 5 | 10 | 80 |
| mapping，506 行读口 | 1 | 2 | 16 |
| **空穴编号表，259 行读口** | **16** | **32** | **256** |
| 待发事件，79 行读口 | 1 | 2 | 16 |
| 合计 | 23 | 46 | 368 |

整网表 99 个该 RAM 硬宏对应报告 792 个 DRAM Slice；计数器 46 个对应 368，停车控制器各 1 个对应各 8，位置跟踪器 6 个对应 48，交叉核对一致。因此 256 是有网表依据的现有存储占用，**不是迁移后净省 Slice 的承诺**。

建议先把 RAM 的无复位同步读与同拍采样的有效性控制分开，结构示意（未实现）：

```verilog
always @(posedge clk) begin
  raw_q   <= empty_ids[empty_address];
  valid_q <= empty_address < empty_total;
end
assign empty_id = valid_q ? raw_q : 9'd0;
```

`raw_q/valid_q` 不加额外复位，保持原来只在时钟沿改变输出的语义；不增加一级读延迟。若推断仍失败，再采用明确的物理 RAM 封装和官方仿真模型。两列读写独立，优先考虑每列一块 ERAM，不能仅凭容量够就合并成一个共享读写口。

必须验证清零、新一轮、无效地址返回零、编号 256/300、连续空穴，以及读写同址语义。正常写地址为旧 `empty_total`，同拍合法读地址必须小于旧 `empty_total`，因此写入槽位当拍应被有效性标志屏蔽。最终要在综合网表中确认 DRAM 真正消失，而不是只检查源码属性。

注意：`ledger` 读地址固定为 511、输出 unused，实际已被工具消除，不能计入可省资源；待发事件表两列只占 16 DRAM Slice，不宜优先花两块 ERAM 去换。

## 3. 优先级 2：标签几何计算改为每帧准备一次

源码：`compact_inspector_osd.v:262–299,363–393`。

目前四个标签分别计算 `lx` 钳位、`ly` 上下偏移/钳位、`rx`、前缀有效性，再进行四路命中判断；选中标签之后又计算一次 `lx/ly`。这些位置基于帧开始锁存的 `obs/record`，整帧不会变化，没必要在每个像素的组合路径重复计算。

建议在**现有**界面准备阶段，用一个位置计算单元分四拍生成四个标签的 `{x0,x1,y0,y1,prefix,valid}`，再供像素流水线直接比较。准备阶段本来就在串行转十进制、写 896 个字符格，有时间复用空间；必须从已锁存的快照读取，不能混入后续实时输入。

保留四路并行命中、最后命中者优先、标签文字/编号/颜色及现有像素延迟；准备完成时间不晚于原来的 `ready`。需要验证标签重叠、边界钳位、帧中输入变化、四种显示逐像素一致。

这是对当前 R28/R36 已经共享字形格式化之后的进一步优化，不能把旧的格式化共享再算一遍收益。新增位置寄存器和复用器也有成本，净节省必须实测，暂不报虚构的 Slice 数。

## 4. 优先级 3：计数标志位共用写地址译码

源码：`observed_classified_pocket_counter.v:380,396–398,419–449,492,507–517,557–559`。

`valid_tracks/used/armed/quarantined/cross_pending` 等 32 位状态向量，分别在多处使用 `found/free_slot/si/mi/emit_track` 做动态单比特写入。这种结构可能产生重复地址译码和多级写选择。

建议明确每个 FSM 阶段的写地址与 set/clear 操作，尽可能共用地址选择和 one-hot 译码；保留全向量清零、回滚与局部更新的原始优先级。不是把所有数组强行并成一个宽 RAM。

必须逐拍保留 NBA 的旧值读取语义，例如 `armed` 的旧值控制本拍是否过线；全向量赋值与同拍单比特赋值的优先级也不能改。该项会触及已验证计数核的内部实现，风险高于编号表读口和 OSD，必须用原 R27B/生产实现逐时钟等价对照。工具可能已共享部分译码，所以未测之前不保证收益。

## 5. 第二阶段：跨时钟状态传输与缓存读选择

### 跨时钟状态传输

源码：`status_cdc.v:8–24`，顶层 `design_top_wrapper.v:706,904,915–918,991–993`。

不能只看综合阶段每个 mailbox 约 2 LUT。物理映射后的 `status_cdc` 实例合计 **1705 logic LUT、3813 seq**；其中帧 metadata crossing 为 572 LUT，active_frame_display 为 451，count_live_display 为 265。这里不是 1705 个可直接删除的 Slice。

需要研究载荷保持、目标寄存、OSD 再锁存之间能否减少不必要的宽数据选择/控制复制，并检查相同源时钟、目标时钟、复位和更新条件的通道是否有实际可合并部分。**帧绑定计数与实时计数具有不同用途和时间语义，不能直接合并。** 源保持、请求/应答同步和目标原子更新必须保留；不能逐位裸同步宽总线、删除两级 token 同步，或无证据删除复位和握手。净收益和位置热点尚未证明，属于架构优化候选。

### 20 个灰度 RAM bank 的读口

源码：`local_edge_surface_check.v:63–75`。

现在 20 个 1024×20 bank 每拍都读取同一低位地址，输出再做 20 选 1。可以研究仅使能选中 bank、分组选择和局部地址控制，维持原有一拍 RAM 读延迟，减少全局扇出和集中连线。但额外译码也可能增加 LUT，不能承诺必省 Slice。

现有 20 bank 分割用于避免泛化 RAM 被填充成 32768 字再挤占其它 FIFO，不应撤销。需覆盖全部合法地址、最后不满 bank、连续换 bank、取消/间隙和缓存数据有效性。

## 6. 不应优先采用的做法

- **缩短编号/帧号、任务队列、丢帧保护或 1 秒保持：** 直接改变功能，当前不采用。
- **看到乘法就改成移位加法：** 实际网表中帧搜索的 `address()`（109 行）就已映射 9 个 DSP；SCALE 多个常系数乘法也使用 DSP。改写可能把专用 DSP 运算移回 Slice，必须先看实际映射。当前 resize/Sobel 已有完整精度的算术重用，不能重复计算旧收益。
- **只去掉边缘模式的菜单选项：** 若“边缘+灰度”仍用同一显示 Sobel 核，通常省不掉完整计算通路。用户若日后明确仅保留 RAW/灰度，再单独评估移除全画面边缘显示核；局部识别边缘算法必须保留。本次没有执行这一取舍。
- **直接删除调试框/几行状态文本：** 多数不影响后端状态采集和传输，可能只省很少的字符选择。优先重构显示实现，让相同信息更省资源。
- **先换 seed 继续跑：** 当前先解决可证实的结构成本，布局热点尚无成功导出结果，不用新的全量布线代替分析。

## 7. 建议的实施与验收顺序（待用户指示后执行）

1. 先单独修编号表读口：最小读写行为对照 + 实际综合映射检查，目标是证明迁 RAM 成功，统计 ERAM 增量与 DRAM/逻辑净变化。
2. 再单独做标签几何预计算：现有 OSD 像素/重叠/快照验证，确认显示效果和准备延迟一致；综合比较净收益。
3. 再评估计数状态写口译码：用原 R27B 成功计数实现逐拍对照，再跑双列编号停车、暂停恢复、连续空穴、五空报警等行为验证。
4. 只合入已证明功能一致且资源有收益的修改，再进行一次完整布局布线，比较**同阶段实际 Slice、关键时序、拥塞/路由完成情况**。综合 Slice* 只能用于筛选，不能替代物理结果。

32 项现有候选软件检查 PASS 是上轮事实，不代表上述尚未实现的方案已经验证，也不代表上板或最终时序通过。
