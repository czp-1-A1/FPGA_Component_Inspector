## 保持判据的时序整理

前两轮实际布线暴露原检测器“区域选择→候选距离比较→RAM写使能”的14级组合路径，最终分别为−1.270ns、−0.552ns，均未交付。当前只把原有候选选择器的空位标志、索引和最差距离共16bit，在已有SCALE阶段锁存，供下一拍COMPARE使用。原选择器循环、阈值和比较式保持；不增加状态或周期。两阶段间区域和候选库保持不变，帧取消仍撤销处理。不是对背面/侧立/有件复核规则的调整。

专门验证实际生产模块SCALE锁存、COMPARE写使能/写地址/距离值，共73,728组输入，覆盖有效位组合、距离顺序/相等、首次空位、末次并列最大及复位取消。发布程序撤销这一小段快照改动后，要求检测器全文件SHA与原RL7一致，避免其他判据悄然变化。受影响的RGB/核心/原生RAW/实际相机网表检查使用新源码重跑，其他未变模块只按实际编译输入SHA复用结果。

## 蜂鸣器

| 项目 | 设置 |
| --- | --- |
| FPGA 引脚 / 顶层信号 | C12 / `O_buzzer_n` |
| IO | LVCMOS33、4mA、PULLUP |
| 有效电平 | 低有效；复位及无报警时为 1，静音 |
| 波形 | 100MHz 时钟，2kHz，半周期 25,000 时钟=250μs |
| 节拍 | 响 200ms、停 300ms；报警期间循环 |
| 触发 | RL7 原有 `relay_alarm`，来自第5个合法连续 EMPTY 的锁存报警 |

这是开发板自带蜂鸣器，无需增加外接继电器/蜂鸣器模块。原送料输出仍为右 J2 第1脚 V2，高有效；原板载5V供继电器接法保持。

第5个连续空穴确认后，送料许可关闭，显示红色 `ALARM 5 EMPTY - MOTOR STOP - K3 CLEAR`，蜂鸣器按节拍鸣响。K2 暂停/继续或 K4 停止不解除报警；K3 清零停止，或明确 K1/SW3 新 RUN，才清掉锁存并静音。正常1～4连空穴和分散空穴不触发这项声报警；其他非五连故障保持原停机行为，不被冒称为五连空穴。

验证包含真实 100MHz 下 50,000,000 个时钟的一整轮 200ms/300ms 节拍及 250μs 半周期；另验证两轮节拍、清除、重触发、复位静音和与五连锁存/手动互锁的集成行为。

## 延迟定义与实现

**测量边界：FPGA 解析接收端 RAW10 帧开始标记，到对应图像经过 OSD 后送入 HDMI 发射器的首个有效像素。** 包括帧采集/读出、ISP、帧缓存和等待 HDMI 扫描的时间；不包括传感器曝光起点到 SOF 的时间，也不包括显示器内部处理、面板扫描和液晶响应。不是光到光延迟。

1. 连续100MHz时钟产生1μs递增计时与寄存 Gray 码。
2. CSI域经两级同步采样该时基；实际 RAW10 SOF 把采集时间放入原128bit桥 SOF 头部的空余位。正常 CSI 包头解析提供恢复时钟后的同步周期，原生夹具建模了该启动过程。
3. 原始 SOF 经原桥进入处理域时获得32bit来源序号；时间与序号成为一个65bit采集元组。它独立于分类结果是否完成。
4. 视频写入器在该帧开始时冻结元组，并与自己的 epoch 一起跨域。只在真实完整像素帧发布时，把匹配 epoch 的采集元组绑定到同一缓存槽。迟到分类元数据不能改写元组。
5. 读出器在选择完整帧时同时选择像素槽、结果及采集元组。显示域从同一个稳定负载邮箱取得对应关系。
6. 在 **OSD 输出端真实首个有效像素** 到来时计算时间差。32拍串行换算后，在本幅画面可见标题行出现前冻结结果，显示本次扫描的来源与延迟，不借用上一帧数值。

界面字段：

| 字段 | 解释 |
| --- | --- |
| `LATENCY 0041.4 ms` | 实际时间差，显示分辨率0.1ms；示例数值不是固件固定值 |
| `FRAME LAG 001` | 已进入处理域的最新原始来源帧号减去当前显示来源号，不是 HDMI 刷新次数差 |
| `SRC 0000001720` | 当前被测显示帧的完整32bit来源号，十进制10位；不是 RUN 内空穴编号 |
| `CAP SOF -> HDMI PIXEL` | 提示测量边界 |

同一来源帧被 HDMI 重复显示时，SRC 不变，当前画面年龄会增加；不会假装每次刷新都采到了新图像。丢帧/取消帧不通过补序号来掩盖。缺少匹配采集元组、读出无效、未来来源或时间差超范围时，显示 `----.-` / `---`，而非上一次结果或按 FPS 计算的常数。

计时器为32bit微秒计数并使用无符号模减，支持正常帧龄跨越计时器环绕。显示有效区间为0～6553.5ms；常规测量以实时连续采集为前提。1μs时基和跨域同步不是纳秒级光学测量；0.1ms显示精度用于本工程板内实时性展示。FPS仅独立显示，不参与延迟换算。

新增单独8ns最大延迟约束覆盖两个32bit Gray 第一同步级；原49项约束和20个图像桥 Gray 实际 Q 验证保留，新增64条实际时间 Gray Q 路径及蜂鸣器输出/报警路径需完成布线审计。

## 演示界面

标题为 `INSPECT RL7 DEMO`，显示 FPS、1280×720、总数、正常有件、空穴、待复核、运行状态、最后编号、空穴编号分页和 K1～K4 提示。隐藏 EXP/GAIN/WB/CFG、RL7十六进制控制行、RD、TR、OF/UF等调试文字；右侧计数框、左侧琥珀补件窗口和对象分类标签保留。图片中的“侧立”未被直接套用于所有复核对象：本轮不修改分类，因此仍按真实语义显示“待复核”。

**显示统计采用互斥口径：正常有件 = 后端有件数 − 待复核数。** 后端仍保留原“有件包含复核”的记录方式，计数/编号事件不改。这样演示页的总数等于正常有件 + 空穴 + 待复核，不因同一个复核件被重复计入两项而产生误解。

K1 新 RUN；K2 自动暂停/继续并保留队列（待机手动电机启停）；K3 单键清零停止；K4 停止保留结果；SW3 上停、下新 RUN。演示构建固定使用计数演示布局，SW4不再切回旧调试界面。旧页的叶模块默认仍为 `DEMO_UI=0`，用于兼容回归；供演示的bit固定使用演示页。后续若需诊断镜像，需按对应时序/构建配置单独生成。

状态包括 READY、RUNNING、HOLD 1S、PAUSED、MANUAL、STOPPED、FAULT、ALARM。相邻空穴已经在窗口内时，仍可能连续停数秒完成多个独立1秒保持，这是原有行为。

## 重建与验证

使用 Windows、Python3.10+、TD6.2.168116及本机合法的 ModelSim2019.2 许可。完整发布中原项目位于 `project/`；在原仓库中位于 `fpga/component_inspector/`。每次输出选新的短英文目录，不覆盖已有结果。

```powershell
python scripts/build_r22_relay.py --keys-v3 --demo-rl7 --seed 1 --source project --baseline-manifest baseline/r22_frozen_inputs.json --work E:/FPGA_WORK/RL7_DEMO_BUILD --td E:/TD
python scripts/audit_r22_relay.py --keys-v3 --adjacent-v6 --five-empty-v7 --demo-rl7 --work E:/FPGA_WORK/RL7_DEMO_BUILD
```

上述路径为例子，`--td`用于构建工具根目录；历史验证脚本默认 ModelSim 在 E:/Modelsim/win64、TD模型在 E:/TD/sim_release，另一台电脑需按实际安装位置适配脚本中的工具路径。安装包/许可证不随工程分发。

验证回执必须与本次冻结637源和实际夹具SHA匹配。完整目标38项：demo单项3、无效显示/实际100MHz蜂鸣器2、蜂鸣器报警集成1、原RL7单项/RGB/真1秒17、兼容5、核心7、新原生RAW/DDR/OSD测量1、实际相机综合网表1、SCALE锁存/COMPARE写回1。原生回放未到停车线，停车/1秒闭环由专门的真实RGB与控制测试覆盖，不能混称原生RAW已完成实际补料。

## 烧录后建议先验收

1. 电机停止，确认真实相机画面更新，演示版标题和延迟数字；静止料带不妨碍来源帧计数递增。
2. K1开新轮，先单空穴/三连验证原停车恢复；未满五连时蜂鸣器应静音。
3. 五连空穴，确认第5个主计数事件触发红字、停机和200/300ms声节拍；K2/K4不能绕过，K3清零后静音。
4. 录完整屏幕，观察 SRC 和 FRAME LAG。重复显示一帧时延迟可增长；无效画面不应显示旧测量值。
5. 验收范围是此版新增声光/延迟界面与原流程回归。识别波动/冷启动、±1mm、吸嘴补料和光到光延迟仍不在本轮已解决声明内。
