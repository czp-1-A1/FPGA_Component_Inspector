## 改动边界

从R50的704个输入冻结候选，只改变 `frame_shape_search.v`。原R27B计数器、观察计数器、双列编号/停车、每列任务容量、五连空报警、完整1秒停靠、按键、电机V2输出、IO/时钟/SDC及四种显示全部保留。

原参考判定路径为：新mask RAM输出→4像素暗度计数→右侧暗度相加→阈值比较→原因位/参考许可。候选在已有 `REF_WAIT` 周期预先计算暗度为0..4的五个布尔结果；下一拍 `REF_CHECK` 用新RAM读出的真实暗度选择结果。没有添加FSM状态、周期或RAM。

只有普通背景参考许可和有件参考质量位采用该准备结果；上下文参考算法、左/右累加器、诊断暗度数值及其原表达式不改。准备寄存器在使用前由原有等待拍赋值，不依赖旧RAM输出。

特别保留原Verilog位宽语义：与8位 `ref_min` 比较时，9位 `right_dark` 加3位 `dark_word` 按9位求值，可能发生模512回绕；诊断里的 `>=256` 则具有32位上下文。准备常量显式为9位，不能把两个场景合并成同一个宽加法。

原REF_WAIT分支仅推进phase，相关暗度、索引、状态及固定配置阈值在消费拍前稳定。复位/新帧/取消会撤销该检查；捕获写优先路径要么保持这些操作数，要么离开参考检查阶段。合法已捕获mask的4个有效位使dark_word始终处于0..4。

## 为什么少了LUT却多了Slice

实际差值可精确分解为 `-27逻辑LUT +144寄存器独占 +0进位 +0分布式RAM = +117 Slice`。物理FF只增加6个，远小于144个新增寄存器独占Slice；增量不能简单理解为“5个准备位需要144个Slice”。当前映射与放置改变了既有LUT/寄存器共享和打包结果。

同一个“详细布局结束”阶段，工具控制组统计为：

| 控制统计 | R50 | R52 |
|---|---:|---:|
| 时钟条目 | 8 | 8 |
| CE条目 | 857 | 862 |
| SSR/ASR条目 | 25 | 25 |
| Control Set | 934 | 937 |

这些是原始工具统计，提示应继续核查控制组合与打包关系；不能把3个控制组直接等同于144个Slice，也不能仅凭CE列把所有FF说成有动态使能。此前实际SYN已证明两列320个观察标志FF的CEMUX均为常开1，不能把简单“删使能”算作新的收益。

## 下一步建议：先审计实际打包，再选择RTL改动

连续两次结果都显示“寄存器独占Slice”会吞掉局部逻辑优化收益。下一步优先用保留的R50实际place DB做只读审计：按模块、控制组合、Slice内LUT/FF占用排列独占寄存器热点，找出能合并写使能、共享写地址或调整无效数据管理的具体银行，而不是再凭RTL行数或单项LUT数量决定。

任何后续改动都必须先证明复位后的外部输出、无效记录屏蔽、ID容量、读写时序及双列功能不变；不能直接删除复位、有效位、模式显示或将当前已经串行共享的控制器再说成可共享收益。确定热点后先做一项可逆改写和局部等价，实际Slice下降且拥挤/时序合适才进入完整布线。本轮没有启动该审计构建或下一项RTL实验。
