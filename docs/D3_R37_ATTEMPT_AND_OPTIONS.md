## 已查明的问题

1. 资源占用低于 100% 只说明能放下。R37 的 Slice 仍达 96.93%，ERAM 为 103/108；局部拥塞、宽总线及 RAM 周边的互连仍可能阻止布线完成。原始工具日志也提示高于 95% 的 Slice 利用率可能延长 P&R 并降低结果质量。95% 是工具提示，不是保证成功或失败的硬门槛。
2. “两个计数工程相加”并不是只增加几条停车控制。早期朴素结构重复了主计数和补件计数，现有 D3 已消除两套重复补件计数核，改为共享实际编号位置跟踪。后续不能再把这项已经完成的优化当作新增收益。
3. 本轮新增 RAM 属性没有实现预期迁移。R36 综合日志第 1457、1460 行 `SYN-5105` 明确报告：`observed_classified_pocket_counter.v(259)` 的读口被识别为不兼容的输出同步复位/读地址异步复位组合，无法推断 bram，回退 dram。综合总 DRAM LUT 仍为 792。
4. 这里的原始 RAM 读 always 块本身没有复位分支，使用的是 `empty_address < empty_total ? empty_ids[empty_address] : 0`；`empty_total` 和上游读地址有复位。不能把问题简单描述为“把 RAM 数组的复位删掉”。应研究读数据与有效性/零填充控制的实现方式。
5. `classified_count_pipeline.v` 将 ledger 读地址固定为 511，输出接 `unused_ledger`。这张表在实际综合中原本就不可观察，不应再将它计为可迁移资源。实际值得核查的是两列空穴编号表；每列最大 300×9 bit。两列地址和读写行为独立，不能仅凭位数小就宣称合成一块 RAM 可以无条件保持并发行为。
