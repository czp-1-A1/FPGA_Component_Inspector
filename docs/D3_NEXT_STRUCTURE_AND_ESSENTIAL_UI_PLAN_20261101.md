## 修改与验证顺序

1. 冻结R55源码、工具版本、IO、时钟、SDC和现有软件证据。先完成精简UI的字段及显示数据源清单，沿消费者追踪，区分功能必需数据与显示专用诊断。
2. 首个候选只处理显示相关结构：删除专用调试格式化/缓存；在已有帧准备阶段锁存标签资格、N/R选择等帧内不变结果，像素路径只做边界命中、选择和字形读取。现有几何和编号前缀已经部分预计算，不重复申报其收益。四标签重叠时保留原来的后命中者优先。
3. 核对所谓共享编号状态：只共享同一列、同一RUN/帧身份、同一更新条件下的同义状态。当前停车已引用主计数输出，没有第二套补件计数核可再次删除。两列编号独立；history_total用于事件连续性验证，不能凭名称相似就用counter_total替代。
4. 同时只读分析post_start到计数控制/RAM的实际Placed路径及全部时钟组；逐级区分组合运算、选择优先级与高扇出。先查明TD官方支持的阶段性路径/数据库导出办法，避免下一次结束仍只有汇总日志。暂不修改成功R27B的判断规则。
5. 若报告证明比较链或选择链是瓶颈，再做保留平局优先级的平衡选择/先并行计算后选择；若控制扇出占主导，则研究在已有准备拍/握手边界形成局部控制。锁存必须使像素、帧号、配置epoch、取消信号一致，不能单独延迟frame_start。
6. 先做有针对性的显示验证：必要信息值、双列标签/编号、重叠优先级、边界、帧中变化、RAW/EDGE切换、RGB/DE/HS/VS对齐。被有意删除的显示不要求与旧屏幕逐像素相同；识别/计数/停车及未变输入必须保持原行为，不能直接沿用旧整屏等价的PASS声明。
7. 再做实际综合/布局筛选：分别记录LUT、FF、Slice、ERAM、最差路径、各时钟组和拥挤范围。综合Slice估算仅作筛选；少量寄存器增加可以接受，但须实测收益。与当前Placed同阶段比较，不预报固定可省多少Slice。无明确收益不进入昂贵全布线。
8. 仅对筛选通过的一个候选运行完整实现。最终核验setup、hold、TNS、原49条约束、CDC和引脚，再完成必要的软件/来源核验与上板验收。seed/策略只允许固定源和约束的有限受控比较，不能替代结构分析；失败后仍停止、保存证据并分析。

保留双列识别、成功R27B双列计数、独立编号/每列32项队列、共用电机、完整1秒保持、连续五空报警、K1～K4/SW3及J2/V2接口。以后交付bit仍额外复制到E:/2026FPGA/BIT_FLASH并校验SHA-256；三个受保护旧bit不替换。
