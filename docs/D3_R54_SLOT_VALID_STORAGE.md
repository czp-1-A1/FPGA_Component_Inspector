# R54：以逐槽有效位编码FSS私有缓存的清零

R53实际打包审计定位到FSS结果缓存750个FF，其中247个位于寄存器专用Slice。继续资源优化时，从R50隔离一项存储编码试验；生产仍为R50，原R27B计数原件和观察计数器、双列停车、显示、IO/时钟/SDC不改。

## 等价关系

原 `recorder_storage` 在复位、新帧、取消、新SOF时整块清零，PACK_SCAN逐槽写入，PACK_FINISH清除重复项。新私有可见字为 `written[slot] ? raw_words[slot] : 76'd0`：清零16个written位即可表示全部零值，raw数据不复位，实际写入时同时写数据并置该槽有效。

不能只依赖全局ready：异常捕获结束可能发布部分包，旧实现的未写槽位仍为零。逐槽有效位保留该行为。重复项写零时，无论该槽是否已写，新的可见值与原来一样为零；其余周期保持。原FSM、所有写入优先级和时刻均保留。

仅在DUAL_STOP且INDEXED时使用新编码，其余配置使用原存储。原主FSM的存储赋值只重命名为legacy变量；在新分支中它没有读者，由综合消除，未复制一份实际结果缓存。公开接口及内部消费者继续读取同值的可见缓存，没有新增FSM状态、流水线周期或RAM。
