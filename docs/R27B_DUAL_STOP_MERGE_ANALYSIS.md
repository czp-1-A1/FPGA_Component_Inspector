## R27B 如何处理结果消失和 C6

这部分须区分三个层次：检测是否产生完整帧结果、真实目标是否能重新关联到旧身份、停车控制器是否持续收到队首空穴的新位置。R27B 对前两层有实际实现和回归；原交接工程没有本任务的双列停车控制，不能把计数恢复直接当成停车恢复已验收。

1. R25 密集场景：SPARSE_ROW_SCAN 记录 T100/T80 前景行的保守并集，只跳过两种阈值均无前景的行，保留完整灰度、暗参考和原分类阈值。已有队列头在前一邻居拍预读，队列字就绪时同拍发首邻居读取；刚写入的唯一队列项仍留同步 RAM 读写间隔。原报告 20 目标末像素后的处理由 140456 周期降至 97595 周期，减少 30.52%。这不是降低时钟频率或关闭 C6。
2. R26 新轮边界：新 RUN 关闭旧 epoch，只允许同拍或下一次源 FS 建立新轮；accept 必须属于已打开 epoch，且不能与 begin/end 同拍。旧结果、旧坏帧尾部不能进入新轮；真正缺帧、缺结果、配置变化和源停止保护保留。
3. R27 过早完成：空场检测可能先给出一次性 search_new，而完整帧证明稍后才到。ISP 用 count_result_pending 保存通知，用 count_frame_proved 保存同一 epoch 的证明，汇合后仅交付一次。FS、取消和坏帧清除 pending，不能跨帧借证明。D2 仍直接把 search_new 接给 proved 门控，缺这处汇合。
4. R27B 物理时序：四槽高距离选择按两列并行、两层平衡比较实现；首空槽、等距选最后槽及首空槽前的 worst 值均保持，没有增加检测周期或改变分类阈值。R26 表面 min/max 比较还使用整数等价式缩短组合链，不改变判断。

密集处理过慢和空场结果过早是相反的两种时序情况，不能只修其中一处，也不能把“标签消失”全部归因于电机速度。两段 D2 视频有 RUN=0/READY，不能凭它们宣称计数报了 C6；是否还存在实际密集截止失败，要用冻结输入复现。

## 对短暂漏检的恢复，比单纯延长超时更关键

R27B 的 `classified_pocket_counter.v` 在生产双列实例中启用 `MOTION_RECOVERY`、`TAIL_RECOVERY`、`ORDERED_HANDOFF`、`RECOVERABLE`、`VELOCITY_ASSOC`、`LOCAL_RECOVERY`。模块参数默认值为零不代表实际双列实例关闭了这些功能，核查必须沿实例链进行。

- **身份与屏幕排序分开**：每列维护自己的 32 个轨迹槽、RUN、逐号事件和分类账；画面中第一个/第二个框的排序不作为身份。已计数目标临时消失时保留旧 ID 用于去重，只有实际下游测量证据满足条件才回收。末尾整帧没有目标不凭空产生新空穴。
- **关联依据真实运动**：同一源帧内连续看到的其他目标可作为运动锚点，缺失期间累加锚点实际位移；真实目标返回后，在有界窗口内匹配旧身份。匹配范围受实测穴距限制，尽量避免相邻穴互相串号。预测只参与关联和候选保留，不生成框、位置或新的越线事件。
- **暂时漏检与持续丢失分开**：短暂缺失保留身份并等待返回；歧义目标局部隔离，其他独立匹配继续处理。已有真实越线证据可以先缓存，等前一个身份的顺序明确后再发布编号。测试覆盖真实返回 8 次观测缺失和未解决 9 次缺失两种情况，不能把这些个例描述成任意速度、任意缺失均可恢复。
- **持续缺失也保留诊断**：`LOCAL_RECOVERY` 可释放被长期缺失目标阻挡的后续真实越线，同时设置持续的 `uncertainty_from`，指明从哪个记录号起编号可能有缺口。它不会按穴距补造缺失目标。这种“保留不确定标记并继续统计”有助于计数，但停车必须同时读该标记；当前停车原型已将非零不确定标记作为禁止按不确定编号动作的条件。
- **候选优先保留**：计数器给检测器每列独立的 `hold_valid/hold_x/hold_y`，优先保留需要等待的真实身份附近候选，降低候选槽截断导致反复丢失的概率。这个提示也不等于该帧已经测到目标。

例如：某空穴一帧没有被识别，R27B 可以留下它的轨迹和此前的真实越线证据；后面重新看到它时继续去重/排序。若一直没有回来，工程可以记录编号不确定并继续接收其他真实目标。补件停车则还要在左侧重新确认该空穴的实际位置，不能沿用它消失前的坐标来完成 1 秒停车。

停车显示的 `F6` 与计数 `C6` 需要分别判定。现有停车控制器在队首位置超过 150ms 未更新后进入一次有界重新定位；同 ID 新位置仍不能恢复才锁定故障。27FPS 时 150ms 约为 4 帧，计数在更长漏检案例中仍能恢复，并不保证这段期间停车位置满足新鲜度要求。`F6` 还要核查来源帧、RUN/ID、候选保留和停机后的运动预测，不能单靠继承 R27B 的 C6 修复宣称解决。
