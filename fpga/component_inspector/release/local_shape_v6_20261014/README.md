# 3528 局部搜索青框 V6

2026-10-14。按用户最新要求，只解决 V5 青框太小、器件轻微移出框便无法完整测量的问题。用户已说明原先所谓实时性下降是严格判定造成的观感，本轮不降低判定门限。

## 本版效果

- 原来的固定 80×80 测量框改为 192×144 局部搜索：[416,608)×[228,372)。固定青色虚线表示搜索范围。
- 在中心附近选取最近的完整轮廓，实线青框按轮廓宽高生成，四周留 2 像素，并随该目标在局部范围内移动。
- 3528 的尺寸、长宽比、85% 前景填充条件不变；小圆空穴、大送料孔、背景仍分别处理。两侧黑带参考跟随目标位置。
- 框、类别、特征与 DDR 视频帧绑定；当前帧缺少检测结果时画面继续显示，隐藏目标框并等待新结果。
- 仍保留绿色处理视图区、四种显示模式、Sobel 边缘显示和现有操作按键。

这是中心附近的单目标局部搜索实验版。候选轮廓中心相对画面中心 (512,300) 的容差为左右 32 像素、上下 24 像素，并要求完整轮廓处于搜索范围内。不等于整个虚线框内任意位置都能检测，也不等于全屏多目标追踪。相较 75 像素高的器件在旧 80 像素框内只剩约 5 像素总余量，本版允许明显更大的中心偏移。

## 实现与验证

新模块 `roi_shape_search.v` 捕获前景/暗像素两位掩码，在搜索行结束后用 4 连通轮廓分离目标。仅从中心 80×64 区域寻找种子，轮廓测量仍扩展到完整 192×144 范围。512 项队列满、轮廓截断、未知形状均不强猜有件或空穴；复杂画面可能来不及生成本帧结果，此时发布完整视频、零检测元数据。

检测结果使用原 115 位原子记录，附带 X/Y 坐标组成 198 位帧元数据。写入器允许完整像素帧在缺元数据时继续发布；显示端读取同一 DDR 槽位的元数据并在活动画面开始锁存。这避免旧框与新视频拼接。

13 项 ModelSim 检查通过，包括 13 个局部搜索案例、真实 RAW10/厂商 ERAM 的 12 帧 ISP 测试、移动框 OSD 检查、元数据取消/恢复、完整 DDR 读写显示与原有回归。另用 OpenCV 独立检查 8 幅实际 ISP 输出的搜索区灰度图，面积、包围框和类别一致。

TD v6.2.168116 完整综合及布局布线通过：Slice 13659/21216（64.38%），ERAM 53/108，DSP 17/40；相对 V5 增加 1112 Slice、5 ERAM、0 DSP。建立余量 +0.245 ns、保持余量 +0.020 ns，TNS 为 0。35 项显式及 2 项厂商 FIFO 延迟约束均匹配，ignored 为 0；没有新增综合/布局布线告警。STA 覆盖率 92.39%，未声明全面覆盖所有外部硬核与异步 I/O。
