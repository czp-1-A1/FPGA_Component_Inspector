# SMALL DUAL R1 优化位置与旧版移植说明

日期：2026-10-19。读者：准备优化旧版工程的 AI 或开发者。

这次主要通过**精简实际综合的显示电路、每路只保留一个候选、缩小小孔缓存**节省资源，同时保留随目标移动的文字。搜索区缩小只是其中一项，不能把全部资源下降归因于虚框变小。

## 1. 先确认参考版本，避免混入阈值修改

| 项目 | 参考身份 |
|---|---|
| 优化前 | 最新阈值四目标版，位流简称 `21dc549f` |
| 优化后 | `SMALL DUAL R1`，位流简称 `6139d4b1` |
| Git 中的优化后代码 | `44e38d2c5b8127d5923890f3e7c5628127b45433`；`5a71d9ab` 是随后上传记录 |
| 工作分支 | `lj4747-contest-work` |
| 完整冻结交接 | [small_dual_20261018](../handoff/small_dual_20261018/README.md) |
| 只含本次优化的差异 | [optimization_only.patch](../tools/optimization_small_dual_20261019/optimization_only.patch) |
| 精确前后身份 | [reference_manifest.json](../tools/optimization_small_dual_20261019/reference_manifest.json) |

`21dc549f`、`6139d4b1` 是 **bit 文件 SHA-256 的前8位，不是 Git 提交号**。`44e38d2c` 相对父提交 `55090063` 还包含此前积累的阈值、显示和测试变更，不能将整个提交当作“单纯资源优化补丁”。

附带补丁直接比较 `21dc549f` 冻结源码与 `6139d4b1` 冻结源码，仅有4个RTL文件和1个SDC文件，不包含此前阈值修改。优化前源码可由交接目录的 `provenance/selected_21dc/inputs.json`、`delta/` 与最终 `source_snapshot/` 重建：某路径有 delta 用 delta，否则用最终快照，再按清单核对 SHA。

若你接手的是 `c093c98b` 或其他旧版，应先比对接口和算法差异，按下文分项移植。补丁只对指定基线负责，不应强行应用到不同版本。

## 2. 实际节省了多少

以下均为 PH1P35MDG324 的**实际布局布线报告**，不是综合预测。

| 资源 | 优化前 | 优化后 | 变化 |
|---|---:|---:|---:|
| Slice | 16442 / 77.50% | 13201 / 62.22% | 少3241，数量约减少19.71%，占用率低15.28个百分点 |
| LUT6 | 14872 | 11722 | 少3150 |
| 寄存器 | 15197 | 12279 | 少2918 |
| ERAM | 104 / 108 | 101 / 108 | 少3块；仍占93.52%，余量不大 |
| DSP | 26 / 40 | 26 / 40 | 不变 |
| PLL | 5 / 6 | 5 / 6 | 不变 |

层级报告进一步说明主要变化位置：

| 层级 | logic LUT 前→后 | ripple 前→后 | seq 前→后 | ERAM 前→后 |
|---|---:|---:|---:|---:|
| `u_experiment_osd` | 2122→662 | 561→22 | 1583→506 | 5→3 |
| `u_isp_top/local_shape_detection$detector` | 1748→1251 | 340→380 | 1097→823 | 44→43 |

`logic LUT`、`ripple`、`seq` 是工具层级列名，不能直接加起来当作 Slice。上表属于整套修改共同综合后的观察；没有逐项单独构建的消融结果，不能承诺“删某行文字就固定省多少 Slice”。候选延续逻辑还使检测层的 ripple 增加了40。

证据：[优化前面积报告](../tools/optimization_small_dual_20261019/baseline_21dc_physical.area)、[优化后面积报告](../handoff/small_dual_20261018/build_evidence/phy_1/camera_to_dsi_display_phy.area)、[完整审计](../handoff/small_dual_20261018/handoff.json)。

## 3. 具体改在什么地方

### A. 精简生产显示电路，而不只是把字画成透明

文件：[experiment_osd.v](../user_source/hdl_source/experiment_osd.v)，搜索 `COMPACT_UI`、`compact_lane_osd`。

原显示模块保留为 `experiment_osd_legacy`，外层用编译期条件 `REGIONS && FRAME_OBJECTS && COMPACT_UI` 选择精简模块。生产参数下只综合精简分支，旧分支留给已有模式和测试，不同时生成两套运行时显示电路。

- 顶栏缩为48像素，保留48×32的安路Logo、EXP、GAIN、相机输入FPS、视图、RUN/CHECK和短版本。
- 删除生产界面中底部HEX/流水号/统计详情、WB常驻细节、MODEL OK/EDGE ON-OFF等长卡片及相应显示选择/格式化逻辑。
- 每路一行中文状态：有件、空穴、有件复核；无有效结果时显示待检测。保留错误汇总到CHECK，未按删除文字的范围删除传输保护。
- 旧显示端每区两个目标的匹配/交换逻辑不再进入精简生产分支。数字1、2表示两条路，不是器件的持久流水号。
- 保留RGB、DE、HS、VS的3拍同步延迟和ENABLE旁路；在一帧首个有效像素锁存该帧使用的结果，不能半帧换元数据。

**用户明确要求文字随框移动。** `compact_lane_osd` 的有效标签以当前目标左上角定位，通常在框上方28像素，靠边时做边界处理；只有待检测标签使用固定搜索区位置。不要为了省资源改回固定有效结果文字。

### B. 缩小中文字库，保留同步ROM

同一文件，搜索 `cjk_memory[0:511]`、`cjk_address`、`u_ascii`、`u_logo`。

生产中文仅用“有、件、空、穴、待、检、测、复、核”和空白：使用512×24位、同步读的小字库，字形内容直接初始化在RTL中。ASCII与Logo原同步ROM保留。

旧OSD共5块ERAM（ASCII1、Logo1、中文3），新OSD共3块（ASCII1、Logo1、小中文1），这里省2块。不要把字库改为大型组合case；也不要因RTL文本变短就认定资源更小。`sim/osd_assets/compact_cjk.hex` 用于独立测试参考，生产小字库不依赖从该测试文件运行时加载。

### C. 四个候选槽改成两个，外部元数据宽度不变

文件：[frame_shape_search.v](../user_source/hdl_source/frame_shape_search.v)，搜索 `LANE_SINGLE`、`SLOTS`、`bank0`、`retain_candidate`、`ref_min`、`PUBLISH`。

新增编译期 `LANE_SINGLE=0`，保持旧模式默认行为；双路生产启用后 `SLOTS` 从4变2，各路只留一个当前测量候选，取消该模式下第二候选的保存、搬移、排序及对应记录逻辑。

不能只改数组长度：`bank0/bank1`、暗参考所属路、剔除已被主体覆盖的小孔候选、主结果选择、记录打包，都同步改成每路一槽的索引。

外部 `region_objects` 仍304位，单条记录仍76位：

| 位段 | 新版内容 |
|---|---|
| `[75:0]` | 上路当前目标 |
| `[151:76]` | 0 |
| `[227:152]` | 下路当前目标 |
| `[303:228]` | 0 |

显示端只抽取两条有效槽。这样可沿用现有跨时钟、帧绑定、DDR和显示接口；不要只把端口改成152位而漏改传输链。

### D. 缩小中央搜索区，选择范围与轮廓测量范围分开

文件：[inspection_region_config.v](../user_source/hdl_source/inspection_region_config.v)，搜索 `COMPACT`；显示与检测都调用同一配置。

新增 `COMPACT=0`。生产1280×720处理画面启用时：

| 路 | 原区域 `[x0,x1)×[y0,y1)` | 新区域 | 新中心 |
|---|---|---|---|
| 上路 | `[400,880)×[240,400)` | `[560,720)×[248,352)` | `(640,300)` |
| 下路 | `[400,880)×[432,600)` | `[560,720)×[368,472)` | `(640,420)` |

每个新区域160×104，横向居中，适配两条水平运动载带。**这是1280×720处理坐标，不是1920×1080传感器坐标；也不是内部640×360掩码坐标。**

仅用区域筛选候选、选择种子/中心，不把主体轮廓硬裁在虚框内。T100全帧主体和暗参考掩码保留；跨虚框边缘的器件仍应测完整外形。ROI缩小不会让全帧掩码按面积同比缩小。

### E. T80小孔缓存缩短，省1块ERAM

文件：[frame_shape_search.v](../user_source/hdl_source/frame_shape_search.v)，搜索 `SMALL_Y0`、`SMALL_Y1`、`small_holes`、`DEPTH`。

旧范围 `[224,616)`，共392处理行；新范围 `[184,536)`，共352行，仍覆盖两区及整体上下各64像素上下文。1280宽、内部半分辨率时，每行160个4位字，深度由31360减至28160；每字另有ignored位。检测层ERAM实际44→43。

缓存不是缩到两虚框内部；边界证书、暗参考及完整孔轮廓仍需要周边像素。重新调整区域时，要一起复核缓存上下界和最大目标外延，不能照抄352行。

### F. 少量历史坐标仅用于候选优先，避免相邻目标来回抢框

文件：[frame_shape_search.v](../user_source/hdl_source/frame_shape_search.v)，搜索 `previous_valid`、`candidate_follow`、`follow_bank`。

单纯“每帧取离中心最近的一件”仍会在相邻两件距离接近时切换。当前方案只增加两路各11位x/y坐标、有效位和候选优先位：当前候选处在区域中心横向±40处理像素内，且距前次选择的曼哈顿距离≤32处理像素时，在同等候选组中优先延续该件；否则仍按中心距离和面积选择。坐标由半分辨率边界相加得到处理坐标，不要再多除一次2。

优先位在原SCALE阶段计算，PUBLISH阶段记录本次有效测量；invalidate清除历史有效性。当前目标离开中央带后可以交给下一件。

这项主要解决抢框，**不是省资源的主项**。每个输出仍来自当前帧重新测量的轮廓，没有沿用旧框或旧判定；不是编码器跟踪、整卷持久ID或必然全检保证。测试已用4像素往返扰动复现纯中心策略失败，再用同一输入和期望验证修正。

### G. 在生产实例真正启用新分支

文件：[isp/isp_top.v](../user_source/hdl_source/isp/isp_top.v)，搜索 `local_shape_detection`。

检测器实例增加 `.LANE_SINGLE(REGIONS)`，从而在双区域生产中启用每路单目标和紧凑配置。只新增参数而不改实例，综合结果可能完全不变。这里未改像素处理算法、相机配置、DDR或时钟。

### H. 只清理被综合删除的显示邮箱约束

文件：[camera_to_dsi_display.sdc](../td_project/camera_to_dsi_display.sdc)，搜索 `SMALL DUAL R1`。

显示消费者精简后，综合删除了 `u_publish_display` 与 `u_wb_process` 的相应目的寄存器。旧版两组各3条max_delay因此失配，早期构建不能验收。最终仅移除这6条命令：每组的payload→D_data、req→req_sync[0]、ack→ack_sync[0]。

移植时必须先从实际综合/路由网表确认同名消费者确实消失。若旧版仍显示或使用这些状态，约束不能删。`u_wb_process` 是这里被优化的状态路径，不代表删除实际AWB像素处理。

其他32条源SDC命令加2条vendor max_delay全部匹配、ignored=0；20位桥接Gray指针和实际扇出继续满足原8ns预算，时钟、I/O和有效路径预算没有放宽。SDC清理属于正确验收的必要适配，不是面积节省技巧。

## 4. 哪些没有作为这次资源优化去改

- 主体T100、小孔T80、Sobel80、正常填充率85%、主体/空穴/定位孔尺寸与侧立保有件分支，均沿用 `21dc549f`。
- RAW/GRAY/EDGE/GRAY+EDGE四视图保留，Sobel仍占12块ERAM；没有通过取消边缘功能省资源。
- 相机解包、ISP像素处理、缩放、完整性/失效保护、DDR、输出视频时钟和接口保持原实现。
- 未修复此前整幅RAW抖动，未宣称解决全部翻面盲点，也未新增传送带计数或停车控制。

若对照更早Git版本看到 `present_match` 填充率或RECIPE数值变化，那属于前一轮28张照片阈值修改；附带的优化补丁不包含这些变化。

## 5. 按旧版需求选择移植范围

| 旧版目标 | 可参考的做法 | 必须保留/重做的内容 |
|---|---|---|
| 也改为两路各一件 | A—H整套对照 | 核对坐标、采样条件、元数据布局与全部验证 |
| 继续保留四目标 | 精简文本、缩字库、编译期裁剪、有效约束核对 | 当前compact显示只读两槽，不能直接替换；应保留四记录/四框/四标签及所需编号匹配，不应用单槽打包 |
| 只优化显示，不改检测 | A、B的设计方法 | 每路目标数、ROI、缓存与原阈值不动；按实际仍存在的消费者保留SDC |
| 需要保留完整诊断页 | 字库/格式化/共享资源方法 | 诊断消费者仍存在时节省会少，不能承诺同样3241 Slice |

这是按用户当前“两条载带各一框”的功能取舍得到的资源结果，不是无条件保持四目标能力的等价重构。

## 6. 补丁使用与验证顺序

1. 冻结接手版本、原测试和基线面积/时序。使用清单核对5个旧文件的SHA；不同基线只做人工对照移植。
2. 在仓库根目录先运行 `git apply --check fpga/component_inspector/tools/optimization_small_dual_20261019/optimization_only.patch`。只有确认基线及目标功能一致后才应用；不要通过忽略失败强行合并。
3. 补丁仅含实现与SDC。测试需另对照 `sim/tb_lane_search.v`、`tb_lane_handoff.v`、`tb_lane_osd.v`、`tb_lane_hd_pins.v`、`lane_ui_0..3.hex`、`lane_ui_spec.json`、`osd_assets/compact_cjk.hex` 和 `run_modelsim.ps1`。保留原测试；旧 `regions_osd` 显式 `COMPACT_UI(0)`，新生产分支用独立像素期望验收。
4. 至少验证：双路正反方向多件依次经过、每路仅一槽、侧立/弱灰有件、空穴/定位孔分离、虚框边缘完整轮廓、4像素往返不抢框、下一件交接、失效清空、文字随框、半帧更新不撕裂、3拍RGB/同步及ENABLE旁路、实际DDR读与串行HDMI，以及四Sobel视图。
5. 使用与仿真相同的冻结输入重新综合和实际布局布线，检查全部时钟/约束覆盖、setup/hold/TNS、Gray实际扇出、Slice/ERAM/DSP/PLL和警告，不能只看综合资源。不同旧版的资源收益以它自己的报告为准。
6. 人工上板核对两条载带位置、实际输入FPS、速度、节距和拖影。每件需有足够有效完整输入帧，HDMI60Hz不等于相机输入帧率；此前合成运动测试不能代替现场全检验收。

参考版已通过14项测试：lane_handoff、lane_search、lane_osd、lane_hd_pins、threshold180、pose180、field180、cal180_holes、cal180_body、regions_osd、hd_pins、sobel_view、sobel_tail、dynamic_sobel。新增运动检查24帧/42条当前结果，交接7帧/14条结果，UI检查4完整栅格/3686400独立像素；新HDMI测试核对两完整720p60帧。日志在 [validation/tests](../handoff/small_dual_20261018/validation/tests)。

参考版最终路由setup+0.103ns、hold+0.020ns、TNS=0、STA覆盖93.12%。这是该参考快照的已测结果；本说明与补丁的生成没有重新运行或更改这些硬件测试。

## 7. 可以直接转交另一个 AI 的任务说明

> 请先读取本文件，核对你手中的旧版与21dc549f冻结基线的差异。学习并按旧版功能要求移植显示精简、小字库、编译期裁剪和缓存优化；只有确认也要两路各一件时，才采用单候选槽、中央160×104区域及相应元数据打包。保持结果文字随当前动态框移动。不要把此前阈值修改混成资源优化，不要取消四种视图，不要沿用旧框伪装稳定，不要放宽有效时序约束。先冻结测试，再改实现，提供实际前后布局布线资源和时序、原功能回归及视频像素验证，明确仍待现场核对的传送速度与漏检边界。附带patch仅适配指定5文件基线，不能强行覆盖不同版本。
